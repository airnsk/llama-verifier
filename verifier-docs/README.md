# verifier-llamacpp — верификатор спекулятивных цепочек как сервис

Сервис-верификатор внешнего драфтера: принимает «префикс + цепочки кандидатов»,
пакетно прогоняет их через плотную целевую модель, возвращает принятую длину и
bonus-токен. Часть асинхронного конвейера (драфтер MoE — отдельно, на другой машине).

Полное ТЗ: [docs/SPEC.md](docs/SPEC.md) (промит хозяина от 06.09.2026, сохранён без правок).

## Ключевые находки из аудита master (06.09.2026)

- **Готового HTTP-API для внешних цепочек нет**: `slot.spec_draft` формируется только
  внутренними имплементациями `common_speculative` (`draft-simple/mtp/eagle3/dflash/ngram-*`);
  в `server-context.cpp` нет точки инъекции токенов извне (grep `spec_draft` — только внутренний путь).
- Механизм верификации в master уже есть: цепочка из `spec_draft` добавляется в батч
  (`handle_last_sampled_token`), потом сличение с таргетом и `common_speculative_accept(n_accepted)`.
- **Выбор реализации V1:** патч llama-server — минимальная инъекция: новый флаг запроса
  `spec_chains` в теле `/completion`, который пишет токены в `slot.spec_draft` в обход
  внутренних драфтеров. Обоснование альтернатив — в RESULTS.md (V1).
- Проверка issue [#27428](https://github.com/ggml-org/llama.cpp/issues/27428): «draft-mtp
  уполовинивает pp на 2-GPU layer split» (field data: 973→532 t/s и хуже, только с включённым
  MTP; одиночная карта −3%). Верификатор MTP не использует → бага не касается; слой-сплит без
  спекуляции в issue не помечен как деградировавший. Для V0 на стенде снять контроль: pp layer-split
  vs `-sm none` без spec.
